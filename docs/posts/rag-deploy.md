# RAG 知识库从 0 到部署上线

最近我完成了一个 **RAG（检索增强生成）知识库问答系统**，并将其成功部署到阿里云轻量服务器。这里记录从功能设计到生产可用的全过程，以及过程中踩过的坑。

## 什么是 RAG

RAG 全称 Retrieval-Augmented Generation，检索增强生成。它把「大模型生成」和「文档检索」结合：先在你自己的文档集合里检索出最相关的内容，再把它和大模型一起生成答案。这样模型就能回答 **私有 / 更新更快的知识**，而不会凭空胡编。

## 技术架构

```txt
前端 (Vue3) ──HTTP/SSE──> 后端 (Python/FastAPI)
                             │ └─ 流式问答（qwen-plus / DashScope）
                             └─ 文档处理链
                                 │ 切片
                                 ▼
                         向量化（text-embedding-v3, 1024维）
```

- **存储**：Qdrant 向量数据库（`rag_documents` 集合）+ MySQL（用户体系）
- **模型**：本地 Ollama（bge-m3 向量）作为开发基线；云端统一 DashScope
- **部署**：Ubuntu 22.04 · Nginx 反代 · systemd 托管

## 核心难点与解决

### 1. 向量维度对齐
本地嵌入模型 bge-m3 为 1024 维，云端 text-embedding-v3 需要显式指定 `dimensions=1024`，否则入库与检索的向量空间不一致，检索会失效。

### 2. 流式问答的 SSE 双写问题
DashScope 已经返回标准 SSE 事件，若后端再包一层 `data:` 前缀，前端会看到字面文本。修复方式是「命中即透传」，不再二次包装。

### 3. 轻量服务器防火墙默认不放行端口
阿里云轻量服务器的 8080 / 443 等端口必须到控制台「防火墙」手动添加规则，否则公网无法访问。

## 部署结果

- 注册 / 登录、文档上传、语义检索、流式问答全链路验证通过
- 通过 Nginx 反代，`/api` 走后端 8000，静态页面走 80
- Let's Encrypt 自动续期证书已就绪，待域名备案通过后启用 HTTPS
