# 4GB 显存下的本地 LLM 提速调优

本地跑大模型，显卡只有 **4GB 显存**，一个简单问题都要几十秒。经过多轮调优，我最终把推理速度提升了 **2.4 倍**，端到端问答从 66~108 秒缩短到 **7 秒**。这里复盘完整过程。

## 问题定位

最初用 CPU 推理 3B 模型，速度约为 **11.3 tok/s**；更换 GPU 后提升到 **27.3 tok/s**。看起来解决了，但很快发现新问题：

> **4GB 显存放不下两个模型**，Ollama 调度器会反复「互踢」——聊天模型和嵌入模型被来回换入换出，反而更慢。

## 关键调优手段

### 1. 固定模型常驻（keep_alive=-1）

把模型常驻在显存中，避免调度器反复卸载重载：

```python
# 让模型一直驻留显存
keep_alive=-1
```

### 2. 降低上下文长度（num_ctx=512）

显存不够时，把上下文窗口从默认的较大值压到 512，明显降低显存占用，多放一个模型：

```python
options={"num_ctx": 512}
```

### 3. 启动时预加载模型

在服务启动脚本里预先 `load` 两个模型，进显存，避免首次问答时才加载带来的卡顿。

## 效果对比

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 生成速度 | 11.3 tok/s（CPU） | 27.3 tok/s（GPU） |
| 端到端问答 | 66~108 s | **7 s** |
| 模型常驻 | 被互踢 | 稳定驻留 |

## 小结

显存受限时，**常驻模型 + 压缩上下文** 往往比盲目升级硬件更立竿见影。如果你的本地推理也慢，建议先查：是不是模型在互相踢？上下文是不是过长了？
